Getting started

Deploy MCP servers to derhead.app and connect them to ChatGPT Business.

Domain structure

derhead.app uses separate Cloudflare deploys for each surface area. This keeps the public website isolated from API and MCP endpoints.

  • derhead.app — public website (Cloudflare Pages)
  • www.derhead.app — redirects to derhead.app
  • api.derhead.app — app API (Cloudflare Worker)
  • mcp.derhead.app — MCP server (Cloudflare Worker, auth required)
  • app.derhead.app — logged-in app UI (coming soon)

Deploy your MCP server

MCP servers live in the apps/mcp workspace. Deploy with Wrangler:

cd apps/mcp npx wrangler secret put MCP_AUTH_TOKEN npm run deploy

Set a strong, random token for MCP_AUTH_TOKEN. This is required before any MCP tool can be invoked.

Connect ChatGPT Business

Once deployed, add your MCP server URL in ChatGPT Business workspace settings:

https://mcp.derhead.app/mcp

Include your auth token in the connection configuration. ChatGPT Business will send it as a Bearer token on each request:

Authorization: Bearer <your-mcp-auth-token>

Start with test tools only. The server ships with ping, get_status, echo, and get_time — harmless tools for verifying connectivity. Do not connect private accounts or data until auth, logging, and tool allowlists are verified in your environment.

Verify connectivity

Check that the MCP server is healthy:

curl https://mcp.derhead.app/health

Test an authenticated MCP request (requires a valid token):

curl -X POST https://mcp.derhead.app/mcp \ -H "Authorization: Bearer <your-token>" \ -H "Content-Type: application/json" \ -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'

API endpoints

The app API runs at api.derhead.app. Public health check:

curl https://api.derhead.app/health

All /v1/* routes require Bearer auth. Set API_AUTH_TOKEN as a Worker secret:

cd apps/api npx wrangler secret put API_AUTH_TOKEN curl -H "Authorization: Bearer <token>" \ https://api.derhead.app/v1/status
  • GET /health — public, minimal response
  • POST /v1/waitlist — public, rate limited (join waitlist)
  • GET /v1/status — requires auth
  • GET /v1/info — requires auth
  • GET /v1/services — requires auth, live health checks

App dashboard

Sign in at /app/ with the same API_AUTH_TOKEN you set on the API worker. The dashboard calls /api/v1/* through the web worker proxy — no CORS setup required.

Build in Cursor

The typical workflow:

  1. Build your MCP server or app in Cursor
  2. Deploy the API to apps/api and MCP to apps/mcp
  3. Set secrets and verify auth + logging
  4. Connect ChatGPT Business to your MCP endpoint
  5. Add real tools to the allowlist only when ready

Read the security overview before connecting anything sensitive.
