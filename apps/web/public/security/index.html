Security

Locked down by default.

Every layer — public site, API, and MCP — is hardened independently. Nothing is exposed unless it has to be.

Defense in depth

derhead.app uses three isolated Cloudflare deploys. A compromise of one surface does not automatically expose the others.

Public site

CSP, HSTS, no API/MCP routes, no secrets, no dynamic server code.

API worker

Auth on /v1/*, rate limiting, CORS allowlist, generic error responses.

MCP worker

Bearer auth, body size limits, tool allowlist, Content-Type validation.

Authentication

MCP server — every request to /mcp requires a valid Bearer token. Tokens are compared using constant-time verification to prevent timing attacks. Failed attempts are logged with source IP and rate-limited.

API — /health is public and returns minimal data. All /v1/* routes require API_AUTH_TOKEN via Bearer header. Store tokens as Cloudflare Worker secrets only.

Authorization: Bearer <token>

Network & transport

  • TLS 1.3 enforced via Cloudflare on all domains
  • HSTS with includeSubDomains and preload on public site
  • Strict CORS — browser requests from unknown origins are rejected with 403
  • Server-to-server requests (no Origin header) allowed for ChatGPT Business MCP clients

Security headers (all Workers)

  • X-Content-Type-Options: nosniff
  • X-Frame-Options: DENY
  • Referrer-Policy: strict-origin-when-cross-origin
  • Cross-Origin-Opener-Policy: same-origin
  • Cross-Origin-Resource-Policy: same-origin
  • Cache-Control: no-store on API/MCP responses

Public site CSP

The marketing site enforces a strict Content Security Policy via Cloudflare Pages _headers:

  • Scripts: same-origin only (no inline scripts)
  • Styles: same-origin only
  • frame-ancestors 'none' — cannot be embedded in iframes
  • upgrade-insecure-requests — no mixed content

MCP tool lockdown

  • Static tool allowlist — no dynamic tool loading. Includes HomeTwin property/measurement/estimator tools plus harmless test tools (ping, get_status, etc.)
  • Max request body: 256 KB
  • POST only on /mcp — other methods return 405
  • Content-Type must include application/json
  • Health endpoint returns minimal info — no tool enumeration in production responses

Rate limiting

Auth endpoints are rate-limited per IP (20 requests/minute). Excess requests receive 429 Too Many Requests. This applies to both API and MCP workers.

Logging & audit

Every API and MCP request writes a structured JSON log line to Cloudflare Workers Logs with:

  • When — ts (ISO timestamp)
  • Who — client IP (ip)
  • What — HTTP method and path (method, path)
  • Outcome — success (true/false) and HTTP status
  • Duration — durationMs

Auth failures (auth.failed) and MCP tool calls (tool.call) are logged separately. Logs never include auth tokens or request bodies.

Error handling

Workers return generic error messages to clients (Unauthorized, Internal server error). Stack traces and internal details are logged server-side only — never returned to callers.

What we don't do yet

Do not connect production databases, private OAuth accounts, or sensitive third-party APIs until you have verified auth, logging, and allowlists in your environment. SSO and per-tenant isolation are on the roadmap.

Responsible disclosure

Report vulnerabilities to security@derhead.app. See security.txt for contact details. Do not test against production without authorization.
