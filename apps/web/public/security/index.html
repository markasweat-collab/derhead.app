Security

Built secure from the ground up.

MCP tools can reach sensitive systems. derhead is designed so you ship with confidence — not hope.

Deployment isolation

The public website, API, and MCP server run as separate Cloudflare deploys on separate domains. The marketing site at derhead.app has no API routes and no MCP tools — it cannot accidentally expose backend functionality.

Authentication

Every request to mcp.derhead.app/mcp requires a valid Bearer token. Requests without a token, or with an invalid token, are rejected with a 401 and logged.

Authorization: Bearer <MCP_AUTH_TOKEN>

Store MCP_AUTH_TOKEN as a Cloudflare Worker secret — never in source code or the public website.

Tool allowlists

Only tools explicitly registered in the MCP server code are available. The current allowlist contains harmless test tools only:

  • ping — returns "pong"
  • echo — echoes back a message
  • get_time — returns the current UTC timestamp

New tools must be deliberately added to the server and deployed. There is no dynamic tool registration that could be exploited at runtime.

Logging & audit

Both the API and MCP workers emit structured JSON logs for:

  • Authentication failures (with source IP)
  • Tool invocations (tool name, timestamp)
  • Request metadata (method, path, duration)

Logs are available through Cloudflare Workers observability. Review them before expanding beyond test tools.

What not to do yet

Do not connect private accounts, production databases, or sensitive third-party APIs until you have verified auth, logging, and tool allowlists in your own environment. Start with test tools, confirm everything works, then expand deliberately.

TLS & transport

All derhead.app domains are served over HTTPS via Cloudflare. MCP communication uses the Streamable HTTP transport — stateless and compatible with Cloudflare Workers' request/response model.
